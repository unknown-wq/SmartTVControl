# SPEC_MOBILE.md — мобильная (вертикальная) версия презентации

Цель: та же презентация, но **читаемая с экрана телефона без зума**.
Источник истины по содержанию, палитре и правилам — `SPEC_v2.md` и уже собранный
`out/build_deck_v2.js` (16:9). Настоящий файл перекрывает SPEC_v2.md **только**
в части формата, сетки, кегля и разбивки на экраны.

## 1. Формат и сетка

| Параметр | Значение |
|---|---|
| Формат | PPTX, вертикальный 9:16 — **7,5 × 13,333 дюйма** |
| Имя layout | `MOBILE9X16` |
| Поле M | 0,42″ со всех сторон |
| Правый край контента | 7,08″ |
| Низ контента | 12,91″ |
| Ширина колонки CW | 6,66″ |
| Зазор между блоками | 0,28″ |
| Скругление карточек | как в v2 (RAD 0,12) |

Одна колонка. Двухколоночные раскладки 16:9 разворачиваются в вертикальный стек.
Допустимы парные плитки в два столбца по 3,19″ — только для коротких чипов/цифр,
не для абзацев текста.

## 2. Типографика (главное отличие)

На телефоне слайд масштабируется по ширине, поэтому кегль считается от ширины
слайда. Минимумы — **жёсткие**:

| Роль | Кегль | Шрифт |
|---|---|---|
| Заголовок экрана | 34–40 pt | Montserrat ExtraBold |
| Подзаголовок / имя | 24–28 pt | Montserrat Bold / SemiBold |
| Основной текст, пункты | **не менее 20 pt**, норма 21–24 pt | Montserrat / Medium |
| Подписи к фото, сноски | не менее 17 pt | Montserrat Medium |
| Крупные цифры-акценты | 54–72 pt | Montserrat Black |

Light и Thin запрещены (как в v2). Межстрочный интервал не менее 1,15.

## 3. Разбивка на экраны

Слайды 16:9 плотнее, чем вертикальный экран, поэтому **разрешено и нужно**
разбивать один слайд на 2–3 вертикальных экрана. Ориентир — 18–26 экранов всего.

Правила разбивки:
- Заголовок слайда переносится на продолжение **без изменений** (тексты заголовков
  менять нельзя — правило SPEC_v2.md), но справа сверху ставится маленький чип
  «продолжение» (17 pt, приглушённый цвет зоны).
- Разбивать только по смысловым границам: карточка/персона/блок не режется пополам.
- Фото не дублируются между экранами одного слайда.
- Цветовая зона (A/B/C) наследуется от исходного слайда — зона не меняется внутри слайда.

## 4. Фоны

Готовые фоны в `out/prepared/backgrounds/` — горизонтальные 2560×1440. Для
вертикального формата их нельзя растягивать. Сделай скрипт
`out/make_backgrounds_mobile.py`, который для каждого нужного фона строит
вертикальный вариант 1440×2560 тем же способом, что `out/make_backgrounds.py`
(процедурная отрисовка в 3× и понижение BOX), с тем же паттерном, плотностью и
непрозрачностью 6–14 %, и с чистой центральной зоной под текст.
Если проще — переиспользуй функции из `make_backgrounds.py`, поменяв канву.

## 5. Изображения

- Только подготовленные копии из `out/prepared/v2r/` и `out/prepared/v2/`.
- Пропорции считать из `sizes.json`, как в v2 — искажение недопустимо.
- В вертикальном формате фото ставится на всю ширину колонки (6,66″) либо
  парой 3,19″ + 3,19″; портреты людей — не мельче 2,6″ по ширине.
- Круглые микрофото — не мельче 2,0″ в диаметре.

## 6. Speaker notes

Заметки к каждому экрану — те же, что в v2 (`parseNotes()` из build_deck_v2.js).
Если слайд разбит на несколько экранов, полная заметка кладётся на **первый**
экран слайда, на продолжениях — короткая пометка «продолжение слайда N».

## 7. Приёмка

1. `soffice --headless --convert-to pdf` проходит, число страниц = числу экранов.
2. Рендер каждой страницы `pdftoppm -jpeg -r 100` — визуальный осмотр **всех**
   экранов: нет обрезанного текста, нет наложений, нет пустот больше 1,5″,
   нет текста мельче минимумов из §2.
3. Проверка «телефонного» теста: рендер страницы в ширину 390 px (ширина экрана
   iPhone) — основной текст должен оставаться различимым.
4. Итоговые файлы:
   - `out/build_deck_mobile.js`
   - `out/presentation_mobile.pptx`
   - `out/presentation_mobile.pdf`
5. Ничего не выдумывать: фактура только из SPEC_v2.md / build_deck_v2.js.
