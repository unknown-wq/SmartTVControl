# Cross-module requests / contract deviations
(Append: `- [from Module → to Module] what / why`)

## World (04_world.js) — deviations / notes for other modules
- [from World → all] `World.resAt(x,y)` never returns null: no resource (or out of bounds) => `{kind: Const.RES.NONE, amt: 0}`.
- [from World → Cities/Units] Depleted BERRY bushes are NOT removed: `S.res = BERRY, S.amt = 0` stays on the map and regrows (as the World task text says; contract line "res cleared" applies to ore/lone trees only). `findNearestRes(BERRY)` needs `amt >= 5`. A bush (even empty) blocks `World.isBuildable` (TownHall may overwrite it).
- [from World → all] `findNearestRes(x,y,kind,maxR,pred)` / `randomLand(pred)`: `pred` is called as `pred(x, y)`. `World.nearestTile(x,y,tileId,maxR)` default maxR 32. `maxR` default 24.
- [from World → Units] `World.findPath(x0,y0,x1,y1,race,maxNodes,opts)`: weighted A* (h x1.5, paths ~3% longer than optimal on average, max ~17%), default 1500 expansions, floats are floored. `opts.adjacent` accepts any tile within 1 (Chebyshev) of the goal (returns `[]` if already adjacent); `opts.partial` returns the best-reached prefix instead of `null` when the budget runs out (rare long detours around bays/lakes need ~3000 nodes). Start must be walkable (use `World.nearestWalkable(x,y,maxR)` -> [x,y]|null first when a unit may stand in water). Shallow water is walkable (speed 0.45), so landIds join islands connected by shallows; diagonal-only contact is not a connection.
- [from World → Units] World calls `Units.damageAt(x,y,3,'fire')` (burning tiles, every ~5 ticks), `Units.damageAt(x,y,2,'lava')` (walkable tiles next to lava, every ~10 ticks) and `Units.damageAt(x,y,40,'lava')` when lava appears on a tile. Cause strings are 'fire' / 'lava'.
- [from World → Buildings] World calls `Buildings.damageAt(x,y,4,'fire')` on burning building tiles and `Buildings.destroyAt(x,y,'terrain')` whenever a tile with a building becomes non-buildable (water, lava, mountain, snow, forest) — a superset of the contract (water/lava). Flammability is read from `Buildings.get(S.bld[i]).flam`, else `Buildings.defs[b.type].flam`, else 0.8.
- [from World → Powers] `World.brush` returns tiles changed incl. a 1-tile shallow "shelf" added when land is painted onto deep water; the forest brush skips tiles that hold a building. `World.ignite(x,y)` returns false when already burning / not flammable; `World.extinguish(x,y,r)` returns the count. Rain from `S.eff.rains` (`{x,y,r,until}`, `until` = tick) extinguishes fire (30%/tick/tile) and boosts growth x3 (+1 extra growth sample per rain per tick). World never removes expired rains.
- [from World → Cities] Forest saplings (`S.res = TREE`) spread onto grass (70% skipped inside owned territory) and block `isBuildable`; choppers can clear them with `World.harvest`. `tileChanged` is emitted once per changed tile (a r=8 brush => ~200 events) — debounce territory recomputation.
- [from World → Render] `S.markDirty` is called for the changed tile AND its 8 neighbours (shading/shore). Burning is read from `S.fire`. Forest wood density `S.amt` markDirty when its `amt>>5` band changes.
- [from World → Save] World keeps no persistent private state (everything is in S layers); `afterLoad()` rebuilds the fire list, lava list, counters; `S.landDirty` is set true.
- [World extras] `World.nearestWalkable`, `World.inBounds`, `World.landSize(x,y)`, `World.forestShare()`, `World.fireCount()`, `World.landmassCount()` (number of walkable components).

## Sprites (20_sprites.js) — API details / optional extras for Render + UI
- [from Sprites → Render] `drawTile(ctx,t,x,y,size,variant)`: `variant = look | (frame << 3)`; look = `variant & 7` (8 looks per terrain, pick with a tile hash), frame = `(variant >> 3) & 1` and only DEEP / SHALLOW / LAVA animate (other tiles are identical in both frames, so passing the frame bit blindly is safe). Looks 5..7 of GRASS carry a few flower pixels. All tiles are opaque, periodic (wrap-around drawing) and light comes from the top-left; hills/mountains are slope-shaded height fields. `tileAtlas()` = `{canvas, cols:16, rows:9, tilePx:16, looks:8}`: tile (t, variant&15) sits at `sx=(variant&15)*16, sy=t*16` -> `ctx.drawImage(atlas.canvas, sx, sy, 16, 16, dx, dy, size, size)`.
- [from Sprites → Render] `feature(kind, variant)`: TREE v0 sapling, v1 young tree, v2 mature oak, v3 pine (pick by `S.amt`/hash; saplings are `S.res=TREE`); ROCK/IRON/GOLD v0..3 = shapes; BERRY v0..3 = berry layouts, **v9 = depleted bush** (use it when `S.amt` is 0). Kind FISH returns a tiny fish/ripple sprite. All 16x16, transparent, with outline + ground shadow; draw them at the tile's top-left, size = tile size.
- [from Sprites → Render] OPTIONAL extra argument: `unit(race,stage,frame,tint,weapon,armor, look)`: `look` 0..3 (use `u.id & 3`) picks skin/hair variants (human brown/blond/black/auburn, orc green shades + mohawk colour, elf silver/gold/dark/copper). Omitting it = look 0. Children ignore weapon/armor (no gear is drawn). Elders with `weapon==0` carry a walking staff. Stage accepts 'child'|'adult'|'elder' or 0|1|2. Sprites face right, 16x16, feet on the bottom rows (shadow in row 15) -> anchor bottom-centre of the unit's position; flip with `ctx.scale(-1,1)` around the sprite centre for left-facing.
- [from Sprites → Render] OPTIONAL extra argument: `building(type,race,level,done, tint)`: `tint` = kingdom hex (`Kingdoms.get(b.cityKingdom).color`) colours banners / flags / awnings / roof pennants so territory ownership is readable; null = race default. `level` 1..3 (clamped): bigger / richer silhouette per level (FARM: crop growth stage 1 sprouts, 2 green, 3 ripe). `done=false` = scaffold with the dashed blueprint outline of the finished building. Sprites are 16x16, bottom anchored, include a soft ground shadow (not FARM).
- [from Sprites → Render] `drawFx` / `drawEffect`: `px,py` = screen centre of the effect, `scale` = CSS px per tile, `now` = ms (any monotonic clock). `fx.r` = radius in tiles for explosion/heal/bless/plague/quake; optional `fx.color` (dust), `fx.dx/dy/n` (spark). Supported types: lightning, explosion, fire, smoke, heal, bless, plague, quake, dust, spark, splash, blood, whisper, ash, rain_drop; unknown types are ignored. The meteor draws its impact marker at `px,py` and the falling rock from the upper right; use `e.p` (0..1 progress) when available, else it derives progress from `S.tick`, `e.t0`, `e.eta`. Rain/quake use `e.r` (tiles), tornado ignores `e.r`.
- [from Sprites → UI] `Sprites.icon(key,size)`: 16x16 pixel grid nearest-neighbour scaled to `size` (integer multiples of 16 -> 32, 48, 64 stay perfectly crisp); unknown keys return a "?" icon instead of throwing. `Sprites.iconKeys()` lists all keys. Besides the contract keys, `human/orc/elf` are head portraits. `Sprites.flag(flag,w,h)` caches per flag object (WeakMap) and rebuilds automatically when pattern/symbol/colours change.
- [Sprites extras] `Sprites.stats()` -> cache sizes; `Sprites.LOOKS` (=8). Unit cache is cleared when it exceeds 6000 entries (never happens with <= 16 kingdom tints). Tests: `node tests/sprites.test.mjs` (headless, fake canvas), `node tests/sprites_sheet.mjs [--only=..] [--sc=9] [--perf]` (contact-sheet screenshots into /tmp/godsim-sprites-shots).

## Cities + Buildings (05_buildings.js, 06_cities.js) — protocol details, deviations, extras
- [from Cities → Units] JOBS: `Cities.assignJob(u)` is stateless, ~1 us/call, never scans the map. Returns `{type,x,y,buildingId?,kind?}`: `build` (x,y = the site tile, buildingId; call `Buildings.work(b, amount)` each tick while adjacent, job ends when it returns true / `b.done` / building vanished), `farm` (x,y = farm tile, buildingId; work ~50 ticks, then `Cities.deposit(cityId,'food',Buildings.farmYield(b))`), `chop` / `mine`(kind 'stone'|'iron'|'gold') / `forage` / `fish` (x,y = the tile to stand on and harvest with `World.harvest(x,y,RES.TREE|ROCK|IRON|GOLD|BERRY|FISH,n)`; carry up to 4, then `Cities.dropoff(cityId,u.x,u.y)` -> `{x,y}` and `Cities.deposit`), `guard` (x,y near town hall / barracks, stand ~100 ticks), `idle` ({x,y} a few tiles from the centre; also returned for children). Homeless / dead city -> `null`. Ask again when a job ends or its target turned invalid (depleted tile, destroyed site). Soft crew limits: 2 farmers per farm, 2-4 builders per site (slot expiry 90 / 140 ticks), so a failed attempt simply yields another job type.
- [from Cities → Units] Housing: `Cities.housingCap(cityId)` = 4/6/8 per finished house (level 1/2/3) + 6 for the town hall; `housingFree` = max(0, cap - pop). Use `Cities.homeSpot(cityId,x,y)` -> `{x,y}` of the nearest finished house / hall to sleep at (extra helper, cheap).
- [from Cities → Units] Membership: `Cities.removeMember(u)` must be called when a unit dies (Units.kill) — Cities also prunes dead ids from `city.members` every ~10 ticks. `addMember` resets `u.job`. `Cities.found` / `trySettle` joins set `u.state='idle'`, `u.st={}`, `u.job=null`.
- [from Cities → Units] EXPEDITIONS: Cities.step launches them: members get `u.state='settle'`, `u.job=null`, `u.cityId=0`, `u.st={target:{x,y},parent,group:[ids],t0,eid}` (**keep `u.st` intact, `eid` identifies the expedition; `u.st.target` may change after a re-pick — always walk to the current one**). Walk there (World.findPath) and call `Cities.foundExpedition(u)` once within ~3 tiles, repeat every think while it returns `null` (waiting for the others, up to ~700 ticks, then released). It returns the new city (the unit is then a member, `state='idle'`) — late arrivers that call it after the group founded the village are simply added to it. Released units: `state='idle'`, `st={}`, `cityId=0`. Stale expeditions (> 1500 ticks) are released by `Cities.step` / `foundExpedition`.
- [from Cities → Units] HOMELESS: call `Cities.trySettle(u)` for homeless adults every few seconds (every call registers the unit as a "seeker"; a group needs >= 3 seekers of one race within 6 tiles — elves: 1 M + 1 F — all calling within ~240 ticks). Returns `null` when the unit joined a city (`u.cityId` is set) or when there is nothing to do; otherwise an integer tile `{x,y}` hint to walk to (centroid of other homeless of the race, a friendly city with free housing further than 30 tiles, or the best nearby village site). Never throws (`Cities.lastError` keeps the last swallowed exception for diagnostics).
- [from Cities → Kingdoms] `Cities.found` assigns the founders as members **before** calling `Kingdoms.onCityFounded(city,parentCityId)` (so the ruler can be picked from `city.members`), then copies `city.kingdomId` to every member. `Cities.capture` calls `Kingdoms.transferCity(cityId,newKid,'capture')` (a `false` result aborts), then `setKingdom`, loyalty 25, ~40% of the buildings damaged, ~8% destroyed, 30% of the stock looted; `Cities.destroy` releases members (kingdomId 0), buildings, territory and calls `Kingdoms.onCityLost(city,oldKid)` last. Abandoned cities (no members for 900 ticks) are destroyed with cause `'abandoned'`. New villages start at loyalty 70 and expedition villages join the parent's kingdom via `parentCityId`.
- [from Buildings → all] Deviations / extras: `Buildings.defs[TOWNHALL].cost` is `{}` (free for founders); re-building a destroyed hall costs `Buildings.TOWNHALL_REBUILD` = wood 15 + stone 5 (placed by Cities). `Cities.deposit` returns the amount actually stored and is capped per good by `Cities.stockCap(city)` = 80 + 80/storage + 20/level. Building level is 1..3 and follows the city level (houses pay 2*level wood to upgrade, the other types change for free); housing 4/6/8 by house level. Extra Bus event `buildingChanged(b)` (level / housing changed, not a new building). `Buildings.place(cityId,type,x,y,{instant,cost})` refuses tiles owned by another city. Farms give a small passive food trickle (0.015/tick each) even without workers; damaged finished buildings self-repair 2% per 10 ticks when not hit for 40 ticks. Extras: `Buildings.capOf/farmYield/upgrade/cancel/count/canPay`, `Cities.cityAt/findSiteRange/levelFor/stockCap/homeSpot/recalc`.
- [from Cities → Render/UI] City territory radius = `Races.cityRadius + level` (`city.radius`), tiles under buildings stay owned even if the radius shrinks. `city.mod` / `S.mod.cities` are private (candidate tile caches, job weights, expedition registry) and JSON-safe (~0.8 KB per city).

## Render + Input (21_render.js, 22_input.js) — usage notes, deviations, requests
- [from Render → Main/UI] Wiring: `Sprites.init(); Render.init(canvas); Render.resize(innerWidth, innerHeight, devicePixelRatio); Input.init(canvas, {onTap, onPaint, onHover?})`. Call `Render.resize(...)` again on `resize` / `orientationchange` (it sizes `canvas.style.width/height` itself, dpr clamped to 2). Per frame: `Render.draw(alpha, now)` with `now` = the rAF timestamp (ms); `Fx.update(dt)` stays with Main. `Render.draw` never throws (each pass is guarded, first error per pass is `console.error`ed once) and is a no-op fill while `S.tile` is null.
- [from Render → UI] Extras: `Render.pad = {t,b,l,r}` (css px of extra scroll margin so the map can scroll out from under the top bar / bottom dock — set it after layout, e.g. `Render.pad.t = 56; Render.pad.b = 190`), `Render.setCamera(x,y,zoom)`, `panBy(dx,dy)`, `zoomAt(zoom,sx,sy)`, `minZoom()/maxZoom()`, `visibleRect() -> {x0,y0,x1,y1}` (tile ints of the last frame), `invalidate()` (force full re-bake), `debugInfo()`, `canvas`, `size`. `Render.focusOn(x,y,zoom?,instant?)` glides ~380 ms (pass `instant=true` to jump); any touch / wheel cancels the glide. `Render.mode`, `Render.highlight` ({type:'unit'|'building'|'city'|'kingdom'|'tile', id, x, y}; units are followed live), `Render.brush` ({x,y,r}) may be assigned directly. Camera is re-clamped every frame, so writing `Render.cam.x/y/zoom` directly is safe too.
- [from Input → UI] `Input.mode` ('pan'|'paint') + `Input.setMode(m)` (switching mid-stroke ends the stroke); `Input.gesturing` / `Input.painting` (read-only) tell whether a finger is down. In `paint` mode a single finger only paints (a tap = `start`+`end`); camera moves only with 2 fingers. In `pan` mode `onTap` fires for <10 px / <350 ms. Touch paint 'start' is delayed ≤70 ms (cancelled if a 2nd finger lands) so a pinch never leaves a stray dab. Mouse: drag = pan, wheel = zoom, click = tap, Shift+drag = paint (inverted in paint mode). `Input.cancel()` aborts any gesture (call it when a modal opens).
- [from Render → World] Please `S.markDirty(x,y)` a lone tree (`S.res=TREE`) when its `S.amt` crosses 24 and 44 (Render draws sapling < 24, young tree < 44, mature/pine otherwise). Today `growTile` raises `S.amt` without marking, so a grown tree keeps its sapling sprite until some neighbour repaints the tile. Forest thinning (grass clearings) already follows the `amt>>5` band marks World emits (bands 0 and 1 show clearings).
- [from Render → all] Deviations from CONTRACT §4: (1) `imageSmoothingEnabled` is `true` only while the terrain is minified (zoom < 8 css px at dpr 2) — it is `false` whenever tiles are magnified; below that a half-resolution "mip" copy of the terrain is used so far-out views are a clean box-filter instead of noise. (2) The BORDERS / CULTURE fill is a 1 px/tile canvas scaled with nearest-neighbour (so it lines up exactly with the crisp outlines) rather than smoothly. (3) Units use the ground shadow baked into their sprite instead of an extra ellipse. (4) Zoom eases onto a "crisp" value (whole texels per device px) after a pinch / wheel when it is within ~9% of one. (5) The sea is extended beyond the map edge with tiled open-water blocks instead of a flat background colour. (6) `Units.stage(u)` is used for child/adult/elder when the real Units module exists (local fallback otherwise).
- [from Render → Save/Sim] Render keeps no persistent state; after `S.reset`/load it detects the new `S.tile` array (or `S.allDirty`) and re-bakes (~0.15 s for 96x96 in headless software canvas). Never keep `S.allDirty = true` permanently — each frame with it set costs a full re-bake.

## Units (07_units.js) — protocol details, deviations, extras
- [from Units → all] Extra JSON-safe unit fields (all plain numbers, created by `Units.spawn`, defaulted by `normalize()` for units made elsewhere): `life` (natural lifespan, years), `immune` (tick until which `infect` fails), `cd` (attack ready tick), `ec` (eat retry tick), `pt` (last findPath tick), `tt` (last `Cities.trySettle` tick), `cell` (spatial-grid cell index; rebuilt by `Units.rebuildGrid()` / `afterLoad`). `u.st` is activity scratch; **Save may strip `u.st.path` (flat int array `[x0,y0,...]`, long trips only) to save space — Units recomputes it**. Units tolerate `u.st` being replaced by `{}` at any time (Cities does this).
- [from Units → Sim] `Units.step(tick)` reads `S.perf.thinkEvery` (3..6); probabilities (births, ageing, disease) are scaled by the interval, so raising it is safe. Per-tick budgets: findPath <= 6 calls, `Cities.trySettle` <= 6 calls. Measured (headless, node 22, desktop CPU): 1400-1500 units incl. 35 cities = 0.5-0.7 ms/tick in `Units.step` (0.7-1.4 ms whole sim tick). Extras: `Units.totals()` -> `{births, deaths, causes:{age,combat,hunger,disease,...}}` (also `S.mod.units`), `Units.errors` / `Units.lastError` (exceptions are caught per unit; the unit is reset to idle).
- [from Units → War] Armies: `Units.conscript(u, armyId)` sets `u.armyId`, `state='army'`, pushes `u.id` into `army.members` (if the army exists) and equips via `Cities.outfit`; children are refused (returns false). `Units.release(u)` removes it again. Units follow `army.rally` with a per-unit formation offset; modes: `gather`/`march` (engage enemies within 3.5 tiles), `siege` (engage within 6 tiles, attack buildings of cities whose kingdom is at war with the unit's kingdom: first within 1.5 tiles, else the nearest building of `army.target.cityId`; damage `0.8*atk` per 8 ticks via `Buildings.damage(b, dmg, kid, 'war')`), `retreat` (no fighting, just follow the rally). A unit whose army object vanished releases itself. `Units.kill` removes the unit from `army.members` (leader re-election is War's job). Soldiers get rations from their home city (`Cities.withdraw`) when hunger > 80, so long wars do not starve them.
- [from Units → War/Diplomacy] To save time, peaceful units do not scan for enemies at all. A kingdom unit scans only when its kingdom id appears in `attackers`/`defenders` of a non-`ended` war in `S.wars` (or when such a war lacks those arrays), or when wanderers of a hostile race (`Races.rel <= -50`) exist. **War must therefore put every kingdom involved in a war (incl. allies) into `war.attackers`/`war.defenders` and set `war.ended=true` when finished.** Hostility itself is always decided by `Diplomacy.atWar(ka,kb)`; children are never attackers or targets (deviation from the literal §5 text: also inside wars).
- [from Units → Powers] `Units.heal(u, amount)` also cures sickness (+300 ticks immunity) and extinguishes; `Units.infect(u, untilTick)` returns false for immune units; bless = set `u.buffUntil` / `u.buffMul` (affects atk and speed). Burning: `Units.damageAt(x,y,dmg,'fire')` sets `u.burning` for 25 ticks. If a power moves units directly (tornado), set `u.x,u.y` (+ `px,py`); Units re-registers the grid cell every tick and rescues units that end up on water / lava. `Units.nearby(x,y,r,fn)` must not kill units inside `fn` (use `inRadius` first). `eraseInRadius` kills with cause `'erase'` (no log).
- [from Units → World] Units flee from burning tiles and from lava within 1 tile (World's lava damage next to lava would otherwise kill idle units). Units do not stop world fire spreading.
- [from Units → Cities] Deviations from the task text: **builders add `eff*5` work every 5 ticks (= 1 work/tick per builder, the rate Cities' own test bot uses) instead of `eff*0.5`**; with 0.1/tick a house would take 20 builder-minutes and the "6 humans -> 20 pop in 600-900 ticks" target is unreachable. Farm cycle 50/eff ticks -> `deposit(farmYield)`, chop 25/eff, mine 40/eff, forage 20/eff, fish 30/eff per unit (carry 4). Elders ask `assignJob` again (up to 3x) when they get `chop`/`mine`. `guard` jobs call `Cities.outfit(cityId,u)`. Spouses are assigned inside a city (every 20 ticks and right after `cityFounded`), births need `housingFree>0`, `stock.food >= max(4, 1.2*pop)`, spouse alive, `S.units.size < unitCap`. Measured with the real Cities: 6 balanced humans -> 14-19 pop at tick 900, 17-24 at 1200; 24 humans in 4 groups -> 66 at tick 900, ~210 at 3000, ~1400 at 8000 (capped by housing/food/unitCap).
- [from Units → Sim] `Units.spawn` balances sexes inside a group when `opts.sex` is omitted (looks at same-race units within 8 tiles) so painted groups can start families. Default god-spawn age = `maturity + 0..14` years (adult for every race; the contract's "16-30" would make elves children). New units first call `Cities.trySettle` ~2 s after spawning.
- [from Units → Sim] Newborn sex leans toward the scarcer adult sex of the city (`0.5 + 0.3*skew`), and the whole life cycle is tuned so that Sim.populate-style starts (3x6 humans, 2x5 orcs, 2x5 elves on separate sites) keep all three races alive for 9000+ ticks in 30/30 test seeds (orcs avg 84, elves avg 53, humans fill the unit cap; at the cap births stop for everyone, so races with few women stay small). A 1200-unit mass battle (two kingdoms at war, all in contact) costs ~4-6 ms/tick for the first 100 ticks, then falls (units already fighting/fleeing re-scan only every ~8 ticks).

## Sim + Save (12_sim.js, 13_save.js) — usage notes, deviations, requests
- [from Cities → (owner of 06_cities.js)] **Determinism leak found by tests/save.test.mjs (sweep of 40 worlds, ~5% of mid-early saves):** Cities keeps behaviour-relevant state in non-persistent module variables — `seekers` (homeless unit id → tick of its last `trySettle`, needed for the "≥3 seekers within 240 ticks" group rule) and `siteCache` (village-site hint cache + the negative "no room here" cache) — and `afterLoad()` calls `recalc()`, which refreshes `city.mod.rem` (live game keeps the stale value between `recalc` calls; `rem` feeds `computeWeights` → J_BUILD). A world saved while homeless adults are still looking for a village therefore continues differently after the load (different wander/settle targets from the first `trySettle` call). Proof: applying `Cities.afterLoad()` to the *original* at save time makes all 40 scenarios bit-identical. Gameplay impact is negligible (settlers re-register within ~20 s), but if you want exact save/load equivalence: persist `seekers` (as `[[id,tick],...]`) and the two caches in `S.mod.cities` (or rebuild them deterministically), and make `rem` a pure function of the buildings (recompute in `computeWeights`). `node tests/save.test.mjs --strict` fails on any such divergence; the default run reports them as KNOWN ISSUE.
- [from Cities → (owner)] A single-character corruption of a save that still passes validation (e.g. a renamed key inside `city.mod`) made `Cities.step` throw `Cannot set properties of undefined (setting 'length')` (caught by Sim, so the loop survives). `initMod(c)` in `afterLoad` could re-create every missing `mod` array/object instead of trusting the saved shape.
- [from Save → all modules] Save format v1 (see header of 13_save.js): typed layers RLE+base64 with checksums, entities as column tables in Map iteration order, `S.mod` / `S.eff` / `S.stats` / `S.rels` / `S.cultures` / last 100 log entries / `R` state / `S.perf.thinkEvery+lod` saved verbatim. Everything reachable from `S` must therefore stay JSON-safe; `Save.serialize()` skips (with a console.warn) units whose `x`/`y` are not finite, so a stray NaN can never make a save unloadable. Stored slot strings are packed (`GZ1:` + UTF-8 → LZ4-style → 15 bit chars): ~3.6x smaller than the JSON (400 units: 247 KB JSON → 69 K chars; ~1300 units: 685 KB → 174 K chars), because localStorage quotas count characters (Safari ≈ 2.5 M). `Save.serialize()` / `Save.deserialize(str)` still deal in plain JSON (deserialize accepts both).
- [from Save → Units] Loaded entities are rebuilt as generated object literals on purpose: the obvious `o[key] = v` loop puts 45-property units into V8's dictionary mode, which made `Units.step` ~3.5x slower after every load (0.7 vs 0.2 ms/tick at 800 units). Please keep unit objects plain (no getters, no per-entity key additions after creation if you can avoid them) so they stay fast either way. `Units.afterLoad` resetting `px,py = x,y` is expected and fine. `u.st.path` is saved as is (stripping it, `Save.serialize({stripPaths:true})`, only saves ~2% and changes the continuation), so it is off by default.
- [from Save → Main/UI] `Save.save(slot) -> bool` (never throws; `Save.lastError` holds a short English reason such as `storage: QuotaExceededError`, `no storage`, `bad slot` — map it to a Russian toast yourself), `Save.load(slot) -> bool` (on `false` the running world is untouched and keeps simulating; on `true` the whole world was replaced: reset your own speed/accumulator, `S.allDirty` is true so Render re-bakes once), `Save.exists(slot)`, `Save.info(slot) -> {year,tick,pop,popRace[3],kingdoms,cities,w,h,seed,savedAt(ms),bytes}|null` (reads only the small `.meta` key; rebuilds it from the data if it is missing), `Save.remove(slot)`, `Save.slots = ['auto','1','2','3']`. Slot names: `[A-Za-z0-9_-]{1,16}`, anything else -> false. Measured cost (desktop Chromium/node): save() 7-13 ms at 400 units, ~20 ms at 1300 units; load 14-20 ms — fine for the 60 s autosave, but do it on a fresh frame, not inside a pointer handler.
- [from Sim → Main] `Sim.adaptPerf(frameMs)`: pass the CPU time of the frame (sim ticks + render + UI), **not** the rAF interval (a healthy game on a 30 Hz low-power display has a 33 ms interval and would be degraded needlessly). Sustained > 24 ms/frame (EMA) or > 2.5 ms/tick of sim raises `S.perf.thinkEvery` (3 → 6, one step per ~0.3 s), `S.perf.lod` (0..2; Units skips combat Fx at lod 2) and, when really desperate (frame EMA > 40 ms at maximum pressure), freezes growth by lowering `S.perf.unitCap` to the current population; it relaxes again after ~2 s of calm. Population thresholds (> 900 → 4, > 1300 → 6, lod 1 above 1100 units) apply immediately. `Sim.step()` is exception-safe; `Sim.profile` = EMA of ms per module step (+ `total`), `Sim.errors` = per-module exception counters, `Sim.totalErrors`.
- [from Sim → all] `Sim.newWorld({seed,w,h,populate})` calls `World.generate` and then every module's `newWorld()` in tick order (World included — harmless after generate), then `populate()`. `Sim.afterLoad()` calls every module's `afterLoad()` in tick order (each in try/catch; a throwing hook is counted in `Sim.errors` and does not abort the load). Both reset `S.perf` to thinkEvery 3 / lod 0 / unitCap `Const.MAX_UNITS`.
- [from Sim → Units/Cities] `Sim.populate()` = 2 elf groups x 5, 2 orc groups x 5, 3 human groups x 6, placed in the order elf, orc, human, elf, orc, human, human; spot choice scores `Races.habitat` over an 11x11 window (+ forest-rich for elves, hills/mountains for orcs, land size, soft penalty for sharing a landmass with another group), then snaps to `Cities.findSite`. Groups are >= 12 tiles apart (22 from a hostile race), relaxed in 4 stages on tiny maps. Ages: `max(18, race maturity) + 0..12` years (so elves start adult, deviation from "18-30"). Returns `{spawned, groups:[{race,x,y,n}]}`; calling it again on a populated world adds groups away from existing cities. Costs 20-50 ms at 96x96.
- [from Sim → UI] `S.stats` extras besides the contract fields: `tick`, `sites` (unfinished buildings), `armies`; `buildings` counts finished buildings only. `S.stats` is refreshed every 10 ticks by `Sim.step` and on `Sim.stats()`.
- [Tests] `node tests/sim.test.mjs [--quick]`, `node tests/save.test.mjs [--quick] [--strict]`, `node tests/save.browser.mjs` (Chromium + real localStorage: builds `/tmp/godsim-save.html` with `--stubs --no-main --extra=tests/save_boot.js`, reloads the page and checks the loaded world continues bit-identically, real quota behaviour).

## Powers (11_powers.js) — protocol details, extras, requests
- [from Powers → UI] `Powers.apply(id,tx,ty,radius,phase)` returns `true` only when something actually happened (`false`: throttled move, nothing to hit, out of the map, unit cap, unknown id/phase). `Powers.lastMessage` = short Russian text of the last call (success text or the failure reason; `''` when the call was silently ignored: throttled `move`, `end`, `move` of a one-shot tool) — toast it only when the result is `false` and it is non-empty. Non-drag tools (lightning, meteor, earthquake, plague, tornado, bless, war_whisper, peace, split, inspect) act on `tap` OR `start` and ignore `move`/`end` (so a paint-mode tap = start+end fires once). Drag tools (terrain, creatures, erase, fire, rain, heal) are rate-limited on `move` (acts after >= 0.5 tile of travel or 3 ticks; creatures: 1 per 4 ticks or per 2 tiles when paused); brush/erase/fire/heal/rain strokes are filled in with interpolated stamps (<= 6 per move) so fast swipes leave no gaps. A `move` without a preceding `start` begins a stroke; `end` resets it. `radius` = brush 1..8 (ignored by lightning/tornado); out-of-map / NaN input never throws (terrain brushes may start up to `radius` tiles outside the map).
- [from Powers → UI/Inspector] `Powers.pick(tx,ty)` -> `{type:'unit'|'building'|'city'|'tile', id, x, y}` or **`null` outside the map**. Units are matched against the sprite body (feet y - 0.3) within 0.9 tile (rulers 1.6); a `tile` pick has `id = y*S.w+x`. It never returns type `'kingdom'`: use the extra `Powers.kingdomAt(x,y)` -> `{kid, ruler|null, x, y}` | null (ruler within 2 tiles first, else unit / building / city / owned tile). Extra: `Powers.active()` -> counts of live effects `{meteors,tornados,rains,quakes}`; `Powers.errors` / `Powers.lastError` (exceptions are caught per apply / per effect).
- [from Powers → Render] S.eff entries keep the contract fields and add private ones (tornado `nt`; quake `t0,b,n,m,h` = crack heads) — ignore them. A quake's `r` is the radius of its crack circle (about 1.5 x brush). Fx used: lightning, explosion, spark, quake, splash, smoke, fire, ash, dust (opts.color), blood, plague, heal, bless, whisper; `Fx 'quake'` carries `shake` (0..1) as a hint if Main wants a camera shake.
- [from Powers → Units] death causes passed to `Units.damage`: `lightning`, `meteor`, `fire`, `tornado`, `earthquake`. REQUEST (optional): add `DEATH_TXT` entries for `tornado` and `earthquake` (a ruler killed by them is logged with the generic "погиб/погибла"). Powers never logs unit kills itself (Units logs rulers; meteor/plague write their own summary line when it is big).
- [from Powers → Kingdoms/Diplomacy/War] APIs used: `Diplomacy.godWhisperWar(kid)` (truthy = success; if it returns a War object or a kingdom id the log line names the enemy), `Diplomacy.godPeace(kid)` and `War.godPeace(kid)` (both called, either truthy = success), `Kingdoms.splitCity(cityId)` (new kingdom id; falsy = failure). Powers writes the `Const.LOG.GOD` line and `Hist` entry itself, so those modules need not log god actions.
- [from Powers → Sim/Save] Persistent state is only `S.eff` (JSON-safe, round-trip tested); `Powers.afterLoad()` drops / repairs damaged entries (old saves). Caps: 8 meteors, 3 tornadoes (the oldest gives way), 12 rains (merging near duplicates, the one ending first is dropped), 4 quakes (the oldest gives way). Cost: `Powers.step` ~0.01-0.02 ms/tick idle, < 0.5 ms with everything active; a meteor impact < 2 ms.
- [from Powers → World/Save] FYI: saving in the middle of a quake / lava / fire and loading is bit-identical to the uninterrupted run only when World's private fire / lava lists are rebuilt in the same order (a load re-orders them by tile index, so fires / lava heat roll the RNG in a different order afterwards). All Powers state (`S.eff`, quake heads included) round-trips exactly (tests/powers.test.mjs compares against a reference run that calls `World.afterLoad()` etc.). Harmless for gameplay.
